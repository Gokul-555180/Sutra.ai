## 1. Security Philosophy & Threat Model

SUTRA.ai is designed from the ground up as a **local-first desktop software application**. Because prompt engineering involves sensitive business logic, proprietary code snippets, proprietary system instructions, and paid AI provider API keys, our security architecture prioritizes **defense-in-depth, zero-surveillance, and minimal attack surface**.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       SUTRA.AI SECURITY GUARANTEES                          │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. Zero Inbound Telemetry     • Zero tracking beacons, no analytics servers │
│ 2. Hardware/Vault Credentials • Keys stored in OS Keyring / Tauri Stronghold│
│ 3. Sandboxed File I/O         • Max 10MB limit, UTF-8 validation, path locks│
│ 4. Restrictive Tauri IPC      • Whitelisted commands only, zero raw shell   │
│ 5. Local Database Isolation   • Encrypted local SQLite, zero remote syncing │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. API Key Protection & Secret Management

1. **No Plaintext Key Storage:** Under no circumstances are provider API keys (Google Gemini, Groq, OpenAI, Anthropic) stored in plaintext files, unencrypted SQLite rows, `localStorage`, `sessionStorage`, or webview cookies.
2. **OS-Native Credential Manager:** Keys are committed to and retrieved directly from the native operating system vault via Tauri native security plugins:
   * **Windows:** Windows Credential Manager (`wincred`).
   * **macOS:** Apple Keychain Services.
   * **Linux:** Secret Service API (via `libsecret` / FreeDesktop Secret Service specification).
3. **In-Memory Volatility:** Retrieved API keys are held in memory solely for the instantaneous duration of an HTTP request dispatched to the respective AI provider, and are cleared from memory immediately upon response completion or failure.
4. **Source Code Hygiene:** No hardcoded secrets, temporary test keys, or `.env` credential files are ever committed to the repository. Automated git hooks and CI scanners enforce this invariant.

---

## 3. Desktop Runtime & IPC Security (Tauri 2)

1. **Explicit IPC Whitelisting:** Tauri's `capabilities` configuration enforces strict isolation. The webview frontend cannot invoke arbitrary system commands, spawn background shell processes, or browse arbitrary directories outside user-selected paths.
2. **Zero Shell Execution:** SUTRA.ai does not permit execution of child processes (`sh`, `bash`, `cmd.exe`, `powershell.exe`). All native capabilities are written in compiled, type-safe Rust.
3. **Payload Sanitization:** All data passing across the Tauri IPC bridge between the React frontend and Rust backend is validated at runtime on both ends using **Zod** in TypeScript and **Serde** in Rust.

---

## 4. File Import & Input Validation

1. **Sandboxed File Ingestion:** When users import context profiles, prompts, or documents (PDF, TXT, MD, JSON):
   * Files must be explicitly chosen via native OS open file dialogs.
   * A hard file size limit of **10 MB** is strictly enforced.
   * Malicious or malformed inputs are rejected prior to parsing.
2. **Path Traversal Prevention:** Relative path notations (`../`, `..\`) are strictly stripped and rejected. File operations are bound to dedicated application data directories.
3. **Data Bundle Validation:** Imported prompt bundles (`.json`) are parsed against comprehensive Zod schemas. If any schema validation fails, the import transaction rolls back without corrupting the local database.

---

## 5. Local Data Protection & Privacy

1. **No Silent Data Ingestion:** Context profiles and personal preferences are never silently injected into prompts. The user maintains explicit visual control over which context modules are attached to an outgoing prompt request.
2. **Offline-First by Design:** The core prompt structuring, rubric evaluation heuristics, template parsing, and local model inference (via Ollama) function completely disconnected from the Internet.
3. **Transparent External Network Traffic:** The only external network requests generated by SUTRA.ai are direct HTTPS requests to user-configured LLM endpoints (`generativelanguage.googleapis.com`, `api.groq.com`, `api.openai.com`, `api.anthropic.com`, or `localhost:11434` for Ollama).

---

## 6. Dependency Management & Vulnerability Auditing

1. **Continuous Dependency Auditing:** Both Node.js and Rust dependencies undergo automated vulnerability auditing:
   * Frontend: `pnpm audit`
   * Rust Backend: `cargo audit`
2. **Minimal Dependency Footprint:** We adhere to a strict policy against frivolous micro-dependencies to minimize supply-chain risk.

## 7. Reporting a Security Vulnerability

We treat potential security vulnerabilities with the highest priority. If you discover a vulnerability or potential exploit in SUTRA.ai:

1. **Do NOT report security vulnerabilities via public GitHub issues, discussions, or social media.**
2. **Preferred Channel:** Use GitHub's **Private Vulnerability Reporting** feature directly on this repository:
   * Navigate to the **Security** tab of [https://github.com/Gokul-555180/Sutra.ai](https://github.com/Gokul-555180/Sutra.ai).
   * Click on **Report a vulnerability** to submit a private advisory directly to the project maintainers.
3. **Alternative Channel:** If private reporting is unavailable in your region or client, open a confidential communication request with the repository owner (`Gokul-555180`) via your GitHub account settings.

### What to Include in Your Report
* Description of the vulnerability and attack vector.
* Step-by-step reproduction instructions or a minimal proof of concept.
* Impact assessment (e.g., local credential exposure, IPC privilege escalation).
* Target OS and architecture (Windows 11, macOS Sonoma, Ubuntu 24.04, etc.).

### Our Commitment
* We will acknowledge receipt of your vulnerability report within **48 hours**.
* We will provide a status update and remediation timeline within **5 business days**.
* Once a fix is verified, a patched release and credit disclosure will be published in accordance with coordinated vulnerability disclosure standards.
